# Decisions and evidence

| Date | Decision | Evidence / reason |
| --- | --- | --- |
| 2026-09-16 | Keep the core on Python 3.10+ standard library; use Bash only for entrypoint/menu. | Seed/protocol/report behavior is tested without a VM; no mandatory pip bootstrap. |
| 2026-09-16 | Pin Ubuntu 26.04 GA, not the mutable latest point release. | Canonical's SHA256SUMS publishes both GA and 26.04.1; a moving URL would defeat reproducibility. |
| 2026-09-16 | Pin the Microsoft Italian x64 checksum, import media manually. | Vendor download links expire; the public checksum table was checked on this date. |
| 2026-09-16 | Require an explicit local QGA MSI trust input plus Authenticode verification. | There is no verified, universal distributor MSI checksum to invent; missing inputs visibly block Windows preparation. |
| 2026-09-16 | Use SATA/e1000e and QGA on COM2 for Windows. | QEMU's channel-win32.c supports isa-serial; this removes the extra virtio driver ISO from the minimal flow. |
| 2026-09-16 | Build Windows boot media from the vendor's efisys_noprompt.bin. | Avoids the DVD key prompt without disguising an assisted install as unattended. Missing image is a hard diagnostic. |
| 2026-09-16 | Only explicit --nudge can send a key; record it before sending. | The original lab specification documents recorder-injected keys masking installer stalls. |
| 2026-09-16 | Dedicated QMP lock for every operation, plus bounded message handling. | Real QEMU smoke test issues six queries through concurrent clients, then captures a PNG. |
| 2026-09-16 | Require token and spontaneous QEMU exit; latch token observation. | Regression tests ensure the host waits after the token and preserves disk/screens on a failure token. |
| 2026-09-16 | Distinguish disk existence, SSH reachability and installation evidence. | A qcow2 header is nonempty before an OS is installed; neither that nor a TCP port proves success. |
| 2026-09-16 | Retain attempted disks and refuse automatic reinstall. | Explicit cleanup is the only path to discarding an attempted disk; logs and timeline can survive retry. |
| 2026-09-16 | Verify executable, unique VM name, QMP path and disk path before signalling. | Test rejects the current Python process and a QEMU command with an unrelated QMP endpoint; force stop uses pidfd. |
| 2026-09-16 | ISO verification cache is only a UI optimization. | Device/inode/size/mtime/ctime changes invalidate it; prepare/install rehash against the versioned pin. |
| 2026-09-16 | Never evaluate .env as shell code. | Regression fixture with a literal command substitution neither executes nor leaks in config show. |
| 2026-09-16 | Reject symlinks and enumerate all selected paths before cleanup. | Regression test keeps both failed disk evidence and the symlink target intact. |
| 2026-09-16 | Do not infer OS-install success from firmware tests. | This development sandbox has no /dev/kvm and no matching ISO; real TCG tests cover firmware/QMP/TPM only. |
| 2026-09-16 | Use a streaming SHA implementation compatible with Python 3.10. | hashlib.file_digest was added later; the CI matrix includes 3.10. |
| 2026-09-16 | Recheck the SSH forwarding endpoint against the running QEMU command. | Editing the port in .env while a VM runs must not redirect a guest command to another local service. |
| 2026-09-16 | Keep xorriso `-iso-level 3` for the Windows boot media; UDF is not required. | A first patch assumed Windows' CDFS cannot read a >4 GiB ISO-9660 multi-extent file and switched to genisoimage `-udf`. Wrong: `../qemu-iso-lab` ships an ISO-9660-only rebuild of the same media carrying `sources/install.wim` at 7,464,366,837 bytes and records `"status": "PASS"` with a live guest agent. Both media boot here; the original is kept. |
| 2026-09-16 | Gate the QGA MSI on the pinned SHA-256 in the guest; record Authenticode instead of requiring it. | virtio-win 0.1.285 ships `qemu-ga-x86_64.msi`, `virtio-win-gt-x64.msi` and `virtio-win-guest-tools.exe` all **unsigned** (no `\x05DigitalSignature` stream, empty PE certificate table). Requiring a valid signature made the documented distributor unusable. The host verifies the digest before staging; the guest re-verifies it. |
| 2026-09-16 | Disable curl's progress meter in the step log. | The carriage-return meter collapsed `steps.log` into a single line, defeating `tail -n 20 -F` in the menu preview and the brief's line-by-line logging rule. |
| 2026-09-16 | Run nothing in the `specialize` pass; start the bootstrap from the seed CD at first logon. | A `RunSynchronousCommand` copying the seed with `Get-Volume` exited non-zero and stopped Setup on the modal "Errore o riavvio imprevisto del computer" for 34 minutes; the passive screenshot is the only thing that said so. Lesson already paid for in `../qemu-iso-lab` (`vmctl/windows.py`, `docs/UNATTENDED.md` "Windows 10/11"). |
| 2026-09-16 | Declare `Microsoft-Windows-International-Core` in `oobeSystem` as well as `specialize`. | Without it OOBE stops on the region and keyboard pages; `HideLocalAccountScreen` belongs in the `<OOBE>` block too. Same source. |
| 2026-09-16 | Keep `FirstLogonCommands` under 260 characters and read the script from the CD. | Setup stores them as HKLM RunOnce values and silently ignores anything longer than MAX_PATH. Same source, verified there in the guest. |
| 2026-09-16 | `AutoLogon/LogonCount` 999, not 1. | An intermediate OOBE reboot must not consume the only autologon before FirstLogonCommands runs. |
| 2026-09-16 | Retry the OpenSSH Features-on-Demand capability. | `Add-WindowsCapability` fails while Windows Update is still starting; a single attempt makes the bootstrap flaky. |
| 2026-09-16 | Stage the rebuilt Windows boot media through `installer.iso.part`. | An out-of-memory kill left a 3.6 GiB truncated `installer.iso`, and the `if not boot.exists()` guard would have reused it as complete. |
| 2026-09-16 | Never pipe a native command's output to `Out-Null` in the guest script. | `sc.exe config` failed and the script threw a bare "QGA service configuration failed": the one line explaining why had been discarded. A `Native` helper now reports the exit code together with the output. |
| 2026-09-16 | Write the QGA service `ImagePath` in the registry instead of `sc.exe config binPath=`. | Windows PowerShell rebuilds native command lines and mangles the quotes around `"C:\Program Files\qemu-ga\qemu-ga.exe" -d -m isa-serial -p COM2`. The registry value needs no quoting round-trip and is read back before the service is started. |
| 2026-09-16 | Create an own, always-enabled firewall rule for port 22 instead of trusting the capability's. | With only `OpenSSH-Server-In-TCP` assumed present, SSH to the installed guest hung during banner exchange (a DROP, not a refusal) while the desktop was up and networking worked. `../qemu-iso-lab` creates its own `vmctl-sshd` rule for the same reason. |
| 2026-09-16 | The completion token proves the bootstrap ran, not that the guest is usable. | Run 3 reached the Windows desktop with OpenSSH installed and still emitted `LAB_FAIL_`, correctly: the agent channel was not configured. The screenshot showed a working desktop while `lab ssh` timed out. |
| 2026-09-16 | `stop` asks Windows over SSH after ACPI and QGA, before any signal. | An installed Windows 11 desktop ignored the ACPI power button for the full 180 s grace with a live session. `../qemu-iso-lab` reaches for `shutdown /s` over SSH for the same reason. Linux is excluded on purpose: it powered off on ACPI in 1.6 s and the lab user has no passwordless sudo. |
| 2026-09-16 | Disable the guest's monitor/standby/hibernate timeouts first thing in the bootstrap. | Windows blanked the framebuffer during a long `Add-WindowsCapability`, so the passive timeline recorded all-black frames (max pixel 0) for tens of minutes. Waking it with `--nudge` would have marked an otherwise unattended run as assisted, so the fix belongs in the guest, not in the observer. |
| 2026-09-16 | The fzf menu is English by default, with `LAB_LANG=it` as the only translated surface. | It had been written Italian-only while the rest of the repo is English, which the brief asks for; a publishable repo should not greet everyone in one maintainer's language. Reasons from `Lab.blockers()` stay English in the API and are mapped for display, falling back to the original text. |
| 2026-09-16 | Menu rows carry a fixed-width `[done]`/`[todo]`/`[blocked]` marker; the reason lives in the preview. | Appending the reason to the label pushed real text past the pane width, so entries read `Elimina tutto salvo ISO e chiavi [bloccato: VM ··`. The marker column also lets the eye scan states down a line. |
| 2026-09-16 | `--layout=reverse --height=100%`, no `printf` header before fzf. | The first entry used to render at the bottom, and each redraw left another "Profile: ..." line behind, so three runs of the loop stacked three stale headers on screen. |
| 2026-09-16 | The tmux log pane splits below the menu, not beside it, and the preview drops its log tail there. | Side by side, fzf got half the window and its preview took another 38% of that, leaving about twenty columns for labels: entries read `Delete the screens··` and the preview wrapped every few words. Below, fzf keeps the full width, and the log has one home instead of two. |
| 2026-09-16 | Split host facts into `core.readiness()` so the prerequisites entry can state its own status. | The entry was hard-coded `[todo]` and stayed `[todo]` on a host where `doctor` exited 0, which is exactly the "state that can lie" the brief warns about. The menu could not call `doctor` because `doctor` reports as it checks; both now read the same facts and only `doctor` prints them. |
| 2026-09-16 | `prepare --dry-run` prints while a VM is running, like `install --dry-run` already did. | The running-VM guard sat before the dry branch, so the one command that writes nothing was the one a live VM could block. |
| 2026-09-16 | The tmux log pane stops tailing `menu.log`, and each run starts with a cleared screen. | The pane repeated, line for line, what the foreground command was printing just above it, and successive runs piled up until it was no longer obvious which output belonged to which command. |
| 2026-09-16 | One `core.open_file()`, detached and silenced, for every artefact handed to the desktop. | `xdg-open` inherited the terminal, so Shotwell's `GLib-CRITICAL` warnings buried the step log, and the 20 s timeout blocked the menu meanwhile. `report --open` now reuses it, so a generated report is one keystroke from being read. |
| 2026-09-16 | VNC console on by default at 5940, with the verdict distinguishing exposed from used. | There was no way to watch or touch a guest other than passive screenshots, and `-vnc` cannot be added to a running QEMU: `query-vnc` returns `enabled: false` and HMP `change vnc` only sets a password. Leaving it off by default hid a whole dimension of the lab; leaving the caveat unconditional would have printed "not provably unattended" on every report until it meant nothing. `query-vnc` reports connected clients, verified against a real QEMU, so the installation loop can record the difference between a port being open and somebody being on the other end. |
| 2026-09-16 | Fixed table layout and one language per report. | `overflow-wrap:anywhere` applied to every cell, so with no column widths the long command column squeezed the rest and broke them character by character: `UTC` became two lines and each timestamp a vertical strip. Headings also carried both languages at once; they now follow `LAB_LANG`, while the Italian quick guide stays as the brief asks. |
| 2026-09-16 | The menu blocks "Start the VM" when the port is held by a process the lab does not own. | Chosen from a `[todo]` entry, `start` refused with "SSH port 2400 is already in use" — correct and safe, but the menu had no way to say so beforehand. `core.port_free()` is now shared by the menu and by `start`. |
| 2026-09-16 | A refused menu entry reports the plain reason and does not print the command. | It raised `ERROR: [blocked]: the VM is off`, marker and all, right under a `$ ./lab stop ...` line for a command that was never going to run. The preview still shows the command, so the menu keeps teaching the CLI. |
| 2026-09-16 | The menu header states the lab's condition, not just the profile name. | With a VM running, fifteen of twenty-seven entries were blocked by that one fact, and moving reasons into the preview meant nothing on screen said so. The header now reads `profile: … · VM running · ISO verified`, so the pattern explains itself. |
| 2026-09-16 | `Esc` leaves the top-level menu, `Ctrl-C` returns to it, any key dismisses the post-command prompt, and the last entry is "Exit the menu". | `Esc` used to open a second chooser where a second `Esc` quit the lab, so the reflex that means "go back" everywhere else could end the session by accident. The brief already asks `Ctrl-C` to return to the menu; `Esc` now behaves the same, and the header names the key that actually quits. Listing `esc` under `--expect` is what separates it from Ctrl-C, which fzf otherwise reports identically as 130 — the reason an extra chooser screen existed. Verified by driving the menu through a PTY. |
| 2026-09-16 | A short, typeable generated password instead of 36 random characters. | The generated password is needed at the graphical console, where `token_urlsafe(24)` is unusable, and a password nobody can type is a password somebody replaces with a worse one. `Virtio-6258` keeps upper, lower and digit so Windows accepts it with complexity enabled, and `config init` now prints it once instead of leaving it to be dug out of a 0600 file. Neither guest accepts it over SSH. |
| 2026-09-16 | Bare `lab ssh VM` opens an interactive session. | It used to refuse without a command, so the easiest thing to want from a lab — a shell — was the one thing the CLI would not give. The one-shot timeout is not applied to it. |
| 2026-09-16 | One SSH probe per menu redraw, with a one-second budget instead of 300 ms. | Entries showed `[todo]` in the list and then refused as `[blocked]: SSH is not answering` when chosen, because the probe was asked twice per screen and gave the guest 300 ms to answer. Measured latency is ~6 ms, but a parallel Windows install starves the guest enough to miss that. A state that flickers is a state that lies, which is the one thing the menu must not do. |
| 2026-09-16 | `prepare` forgets the pinned host key for its port. | A reinstall gives the guest a new identity, so every reinstall met the user with REMOTE HOST IDENTIFICATION HAS CHANGED and no way forward from the menu. The removal is announced, because silently discarding a host key is worth a line of output. |
| 2026-09-16 | The smoke tests pick a free VNC pair in 5900-5998 instead of inheriting the default. | Enabling VNC by default made them collide with a real lab VM holding 5940 — caught by the new port guard, which is what it is for, but the tests must stay hermetic. They now also assert the console is up with no client attached. |
| 2026-09-16 | CI gets the TCG smoke tests on every push; a full emulated install runs on tags. | The smoke tests boot real firmware without `/dev/kvm` in about five seconds, so they belong on every commit and were simply missing from CI. A whole installation is a different animal: 370 s under KVM here, far more emulated, 2.7 GB of ISO and a qcow2 past 6 GB on a runner with little free disk. Gating every push on that would buy a slow, flaky signal; a tag and a button buy the same evidence at the moment the repo claims to be releasable. |
| 2026-09-16 | The graphical console always brings a USB tablet; sound is opt-in through `LAB_AUDIO`. | VNC sends absolute coordinates and the guests had only a PS/2 mouse, so the pointer drifted away from the real one; `usb-tablet` is plain HID and needs no driver in either guest. Audio stays off because the guest plays through the host's daemon, which a headless host or a CI runner does not have, and naming a missing backend stops QEMU from starting at all. Verified that pipewire, pa and alsa all start here. |
| 2026-09-16 | `LAB_DESKTOP=1` adds a desktop to Ubuntu Server, best effort. | The pinned media is Server, so the console we just added showed a text login and nothing else. Installing it as a late command with a timeout and a warning, rather than in `packages:`, keeps a rolling archive from failing an install that is otherwise complete — the same rule the guest agent already follows. |
| 2026-09-19 | Replace the `ubuntu-26.04` profile with `lubuntu-26.04`, where the LXQt desktop is required rather than optional. Supersedes the `LAB_DESKTOP` row above. | A flag that is off by default meant the documented, tested, screenshotted outcome was still a text console, and the best-effort late command could report a successful installation of a guest that had no desktop at all — exactly the "state that can lie" this log keeps warning about. Making the desktop part of the profile's identity removes the branch instead of hiding it. `LAB_DESKTOP` is still parsed in existing `.env` files and ignored, so an old configuration does not become a hard error on upgrade; a regression test feeds both `0` and `1` and asserts the desktop is installed either way. |
| 2026-09-19 | `lubuntu-desktop` and `qemu-guest-agent` move into Subiquity's `packages:`, and `apt.fallback` becomes `abort`. | With `fallback: offline-install` an unreachable mirror produced a server-only guest that still emitted `LAB_OK_`, so the completion token would have certified the one thing the profile promises. Aborting turns a missing mirror into a failed installation with logs, which is recoverable; a silent downgrade is not. The cost is that this profile now requires network access, which the README states rather than discovers. |
| 2026-09-19 | The seed verifies the desktop in-target, with no `|| true`, before the completion token is written. | `packages:` succeeding is not the same as a usable graphical login. `desktop.lubuntu_check()` asserts the package is `install ok installed`, `lxqt-session` is on PATH, the session file is non-empty, the default target is `graphical.target` and SDDM is enabled; it runs as a late command, and a non-zero exit takes the error path instead of the token. The same function, plus `display-manager.service` being active, is what `up` asks the booted guest over SSH — one definition of "installed", shared by the installer and the host, so the two cannot drift apart. |
| 2026-09-19 | `up` records `desktop-ready` and takes a screenshot only after the running guest answers that check. | The old wait proved a TCP port and an SSH key, which the log already records as insufficient evidence of anything above the network stack. The extra event and frame cost one SSH round trip and make the report say which guarantee was actually observed. |
| 2026-09-19 | The menu opens as a five-step guided path — environment, ISO, preparation, installation, use — with one recommended action, and the old flat list moves into submenus. | Twenty-eight entries in one list made the first question "which of these am I supposed to press?", and the answer was derivable from files the lab already reads. The recommendation is computed from those facts only: it never infers success from a disk being present or from SSH answering, it sends an unvalidated attempt to the report instead of offering a reinstall, and while an operation holds the lock it offers a refresh rather than a second action. Navigation rows carry `nav:`/`profile:` ids that the Bash loop consumes itself, so no screen change can reach the action dispatcher or touch a lab file. |
| 2026-09-19 | The seed writes SDDM a drop-in that applies `LAB_KEYBOARD` to the greeter. | The first installed guest reached its graphical login offering `Layout: us` while `/etc/default/keyboard` and `localectl` both said `it`: SDDM starts the greeter on an X server of its own and does not read the system's keyboard configuration. The console password is typed at that screen and `-` is not in the same place on the two layouts, so the one credential this profile exists to hand you could be mistyped at the one screen that needs it. `/etc/sddm.conf.d/90-lab.conf` points `DisplayCommand` at a script that runs the distribution's `Xsetup` and then `setxkbmap`, and the check requires `setxkbmap` to exist rather than let a missing one leave the greeter quietly on `us`. Verified on a live guest: the greeter came back reading `it`. |
| 2026-09-19 | `LAB_AUTOLOGIN` defaults to 1, and what proves it is the active session on seat0. | The profile exists to hand someone a usable desktop, and stopping at a password prompt for a generated password is most of the way back to the text console it replaced. It is a setting because autologin means anyone who reaches a running VM's graphical console has the session, which is not every host's bargain. The obvious check - a session exists for the lab user - would pass on any guest, because the SSH connection doing the checking makes one; the automatic session is instead the *active* session on seat0, and it must belong to the lab user rather than to `sddm`. Both directions were exercised on a live guest: with the drop-in the check passes, and with `[Autologin]` removed seat0's active session reads `sddm` and the check fails. |
| 2026-09-19 | `recover` reads a lost verdict back out of the serial logs, and says that it did. | The first real installation of this profile passed - token, then a spontaneous poweroff - and the lab recorded none of it, because the background worker that watches for exactly those two facts had been killed when the menu it was launched from was restarted. The evidence was on disk the whole time and nothing read it. Recovery searches the live serial log and the archives `start` makes (QEMU truncates a `file:` log on every boot, so the token is often in neither the obvious place), and refuses a running VM, a missing attempt and an attempt that already has a verdict. What it cannot establish is that QEMU exited on its own, so the outcome it writes carries `recovered; QEMU exit not observed` instead of borrowing the wording of a watched run. Run against the real lost attempt, it found the token in `serial-1789821625642098850.log` and moved the guided menu from step 4 to step 5. |
